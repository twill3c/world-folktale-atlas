# L-DL7 — 線形写像が効かなかった理由を三つに分ける(2026-09-18)

## 問い

L-DL6 で、和訳対から学んだ線形写像は差し引き(学習なし)に勝てなかった。
**理由を分けないまま e5 本体の微調整(Colab)に進まない。**
材料が弱いのか、目的がずれているのか、容量(線形)が足りないのか(SPEC §3 H-10)。

## 測ったこと(取り分けは L-DL6 と同じ 10 文化圏)

| 分ける対象 | 実測 | 判定 |
|---|---|---|
| 材料 | 取り分けた 6,089 対で**相互最近傍率 0.892**(日→原 0.934・原→日 0.916) | ✓ 材料は強い |
| 目的の不一致 | 段落 → 段落: 差し引き **0.934** / 回転 0.956 / 非線形 0.965(+0.031) | ✗ |
| 容量 | 段落 → 話: 差し引き 0.810 / 非線形 0.828(+0.017) | ✗ |
| 目的に合わせた学習 | 段落 → 話: 0.810(±0.000) | ✗ |

非線形は 2 層(384 → 512 → 384・GELU・残差)、InfoNCE(温度 0.05)、AdamW、10 エポック、
バッチ 256、種 20260918。**設定は測る前に決め、途中で変えていない。** 学習は CPU で数十秒。

## 結論 ── 微調整には進まない

- 登録どおり、Colab へ進む条件は「容量が足りないと示せたとき」だけで、それは示せなかった
- **上限に当たっている。** 差し引きだけで段落対の 93.4% を当てており、材料の相互最近傍率 89.2% とほぼ同じ高さ。
  学習で足せる余地がそもそも小さい
- **残った誤りは言語の問題ではない。** 外した 11/58 のうち 36.4% は、1 位が**同じ本の別の話**だった
  (「Fire and Anansi」を探して「Anansi in Monkey Country」、
  「The two Friends who set off to travel round the world」を探して「The coming of Men」)。
  日本語と英語を近づけても、**同じ本の中で書き出しが似ている**ことは直らない
- 非線形は独英グリム(訳を通していない外部の物差し)を 0.885 → 0.962 に上げた。
  良くなってはいるが、採否の物差しは段落 → 話 の P@1 と決めてあるので採らない

## 踏んだこと

- **`hash()` をキャッシュのファイル名に使った。** Python の文字列ハッシュは実行ごとに乱数化されるので、
  書いたプロセスの外からは読めない。埋め込みと学習を同じ実行でやっていたので緑のまま通り、
  別プロセスの診断で初めて落ちた → `hashlib.sha1` に変えた
- **キャッシュが入力の指紋を持っていなかった。** 和訳が 620 → 656 話に増えたのに古い行数を返し、
  IndexError で気づいた → 対の数を名札に書き、食い違ったら作り直す・読み出しでも落とす
- 和訳が増えたので L-DL6 の測定もやり直した(9,212 → 10,939 対)。**結論は変わらない**。
  古い数字は消さずに SPEC に残してある

## 次にやるなら

- 残る誤りは「同じ本の中の似た書き出し」なので、**言語ではなく本の中の区別**が課題になる。
  たとえば窓の位置(冒頭か中ほどか)を手がかりに加える、同じ本の話どうしを離すように学ぶ、など
- ただし**これは意味検索の質(G-19 0.767)としてはすでに帯を通っている**。
  直す動機は「もっと当てたい」であって、「壊れている」ではない
