## 1. 一つの文化圏に二冊、原語が違う

ドイツ語圏は二冊からなる。

| 本 | ID | 原語 | 話数 |
|---|---|---|---|
| Grimms' Fairy Tales | DE-2591-NNN | 英語(19 世紀の英訳) | 64 |
| Deutsche Märchen gesammelt durch die Brüder Grimm | DE-77905-NNN | ドイツ語(原典) | 62 |

後者はこのアトラスで唯一、英訳を経由しない資料であり、目玉 G-05(交差言語オラクル)の
片側でもある。**和訳はそのオラクルには一切使わない**(自明に当たってしまい証拠にならない)。

二冊には同じ話が重なって入っている。ここで方針を一つ決めた。

- **物語としての固有名が両書で同じなら、日本語も揃える**
  (赤ずきん、ホレおばさん、いばら姫、灰かぶり、忠実なハインリヒ、ミソサザイ、「ひと打ちで七つ!」)
- **二つの原文で綴りや名前そのものが違うなら、訳し分ける**
  - Jorinde/Joringel(独)→ ヨリンデ/ヨリンゲル、Jorinda/Jorindel(英)→ ヨリンダ/ヨリンデル
  - Ilsebill(独)→ イルゼビル、Ilsabill(英)→ イルザビル
  - Rumpelstilzchen → ルンペルシュティルツヒェン、Rumpelstiltskin → ルンペルシュティルツキン
  - **Sneewittchen → 白雪姫、Snowdrop → スノードロップ**
  - **Drosselbart → つぐみ髭王、Grisly-beard → もじゃ髭王**

後の二つは同じ人物だが、英訳者が別の名に置き換えている(鶫の嘴 → 古いモップ)。
同じ日本語にすると、英訳者が何をしたかが読者から消える。**訳し分ける方が資料に忠実**である。

## 2. 低地ドイツ語の扱い

独語本の 008・020・023・034 は低地ドイツ語で書かれている。原文には高地ドイツ語による
方言語の括弧書きの注釈が混ざっているが、**これは日本語の中に溶かし込み、括弧は再現しなかった**。
日本語にはその対応物がなく、括弧を残すと原文にない注釈が本文に居座ることになるからである。
代わりに register(語り口)を土俗寄りにして、地の文との差をつけた。

## 3. 数の検査 T-JA-06 はドイツ語圏で一度も発火しなかった

独語本も英語本も、数をすべて語で綴る(`seven`/`sieben`、`three hundred talers`)。
`\d` を含む段落が原文に一つも無いため、T-JA-06 の条件(同一段落に相異なる算用数字が 2 個以上)が
そもそも成立しない。ノルウェー本(Dasent 1859)と同じ性質である。
**この検査は「原文が算用数字を使う本」でだけ働く**と、改めて確認できた。

## 6. 固有名詞の訳語一致は「原文を grep してから」

「この話は独語本にもあるか?」を記憶で判断しない。毎回 `scratchpad/tr38/DE-77905-*.txt` を
原語のキーワードで grep し、当たった話の既訳(`batch-04xx.json`)を実際に開いて表記を読んでから
訳し始めた。今回 4 回 grep して、2 回は「独語本に無い」と分かり(Das Bürle、Machandelboom の
歌の文句は独語版と英語版で内容そのものが違う)、自由に訳せた。
**「たぶん同じ話だから揃えよう」は、原文が違えば誤りになる。**

## 7. 出荷の確認は、L37 と**逆向き**に壊れた

L37 では「本番を確かめないまま `loop_end success` を書いた」(失敗を成功と報告)。
それを直した ship38.sh は、今度は**成功を失敗と報告する**ところだった。

原因は一行、ポーリングで数える鍵名を間違えたこと。

```python
# 書いたもの(常に 0)
sum(1 for x in s if x.get('translation',{}).get('ja'))
# 正しい(index.json の実際の形)
sum(1 for x in s if x.get('ja'))
```

`index.json` の各話は `{"id": ..., "ja": true, ...}` という平らな形で、`translation` という
入れ子は**話の個別 JSON**(`/data/stories/ID.json`)の側にしかない。二つの形を混同した。

本番は push の数分後にはもう 1,113 話になっていたのに、スクリプトは 40 分ポーリングしてから
`SHIP_FAIL_POLL` で落ちる軌道に乗っていた。気づいたのは、待つあいだに手で curl して
**同じ式を試したら 0 が返った**からである。

**教訓**: ポーリングの式は、**走らせる前に手元の同じファイルで試して、期待値が出ることを確かめる**。
`public/data/index.json`(これから配る当のもの)に同じ式を当てれば 1113 が出るはずで、
0 が出た時点で式が誤りだと分かる。**確認の道具自体に陽性対照を通す**、ということ。

HC-256 の追記(1)〜(4)に **(5) 判定式は手元の同じ形のデータで先に通す** を足す。
