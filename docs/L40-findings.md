# loop_040 — 画面の散文がデータと矛盾していないかを洗う

**見つけた矛盾 3 件、直し 3 件、足した検査 3 件。pytest 101 → 104 件。**

## 1. 同じ画面が矛盾したことを書いていた

loop_039 を閉じたあとに散文を洗い直したら、**同じ画面が矛盾したことを書いていた。**

`/classic/` の対応分析は、本文が `c.correspondence_analysis.n_books` を読んで
「本 32 冊 × 頻度上位 200 語」と正しく書いていたのに、**すぐ下の図の題は
「全 29 冊」とハードコードされたまま**だった。抜いた図の題も「28 冊」で、実際は 31 冊。
`/about/` の DL 総括表も「英語 768 話から」で、実際の候補は 830 話。

**どれも機械の検査は全部緑だった。** L-DL14 で「コーパスが増えたら下流の測定を
全部数え直す」と書いたが、**数え直す対象に「図の題」と「表の本文」が入っていなかった。**

直し方は数を書き換えるのではなく、**データから引くようにした**(`n_books` を題に差し込む、
`getShapeEval()` から候補数を読む)。書き換えるだけでは次に本を足したときまた古くなる。

### 検査を足した(`tests/test_prose_counts.py`、3 件)

1. README 冒頭の三つ組(話数・冊数・文化圏数・語数)がデータと一致する
2. 画面が「全 N 冊」「N 冊中」と**総数や分母を主張**したとき、その N がデータにある
3. 対応分析の二枚の図の題が、その図が実際に使った冊数を書いている

**2 を「N 冊」全部に広げたら緑に保てなかった。**「6 冊を足して」「1 冊なら」のような
総数でない数え方まで落ちるからである(HC-002: 自分で直せないものをゲートにしない)。
総数・分母を主張する言い方だけに絞った。

**陽性対照を二つ通した。** (a) 検査が実際に見ている主張を印字して 2 件(32 と 33)あることを
確かめ、**主張が一つも無ければ落ちる**判定を検査自体に埋めた(空振りの防止)。
(b) ビルド出力に `全 99 冊` を仕込んで、2 件とも落ちることを確かめてから戻した。

## 3. 残した判断

- **履歴として書いてある冊数は直さない。** `/gates/` の H-03 の表(L1 11 冊 / L4 21 冊 /
  L8 27 冊 / L9 28 冊 / L39 31 冊)は「その時点で測った数」であって、いまの数ではない。
  ここを現在の数に書き換えると、帯を動かさずに測り続けてきた記録が消える
- **`/classic/` の「本が 30 冊から 33 冊に増え」も直さない。** loop_dl14 で判定が
  ✗ → ✓ に変わった理由そのものなので、増える前の数が要る
