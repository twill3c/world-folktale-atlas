# L5 実測記録(2026-09-09/10)— 段落対訳の器と、和訳のはじまり

全 709 話の和訳を目指す。**複数セッションの仕事**なので、器と検査を先に作り、
割合を毎回画面に出しながら積む方式にした。

この回で **22 話(3.1%)/ 語数で 18,205 語(1.5%)**。**全 22 文化圏に和訳が 1 話以上ある。**

---

## 1. なぜ掲載できるのか

| 論点 | 判断 |
|---|---|
| 権利 | 収録 709 話はすべて**米国パブリックドメイン**。台帳に `derivative_use: true` を記録済み。翻訳して公開することは妨げられない |
| 設計書との整合 | §41 が「原文 → 権利確認済みの既存翻訳 → AI 翻訳(補助表示のみ)」の優先順位と、`translation_type = AI_GENERATED` の明示を定めている |
| 訳文の権利 | 訳文は新しく作った著作物で、こちら側にある。既存の published 訳を写したものではない |

## 2. 必ず守る四つ

1. **和訳を Embedding に入れない。** 入れると G-05 / G-07 / H-03 の測定が汚れる
2. **和訳を交差言語オラクルに使わない。** 同じ本文の訳が原文を引き当てるのは**当たり前**で、
   何の証拠にもならない。目玉の物差しは独英の同一物語 26 組のままである
3. **段落を一対一で対応させる。** 対応のずれは、割り方が二箇所にあると必ず起きる。
   段落の割り方は `etl/paragraphs.py` に一本化し、**原文の段落配列も配って**、
   画面が割り直さないようにした
4. **部分訳である間は割合を画面に出す。** `/translations/` に全体と文化圏ごとの進捗を出す

## 3. 取り込みの検査(落ちたら入らない)

| ID | 検査 |
|---|---|
| T-JA-01 | 段落数が原文と一致する |
| T-JA-02 | 空の段落が無い |
| T-JA-03 | 全段落に日本語の文字がある(訳し忘れの英文が残っていない) |
| T-JA-04 | キリル文字・ハングル・制御文字が混じっていない |
| T-JA-05 | 日本語の文字数 ÷ 英語の語数が 0.9〜4.5 の帯に入る(段落の取りこぼし検出) |
| T-JA-06 | 原文の算用数字がすべては消えていない |

22 話すべてが一発で通った。

## 4. 和訳を作ろうとして、コーパスの欠陥が二つ見つかった ★

**段落を並べて初めて見えた。** 集計量(語数・字種・件数オラクル)では原理的に見えない。

### (1) 709 話中 137 話(19%)の末尾に、次の話の番号が残っていた

見出しが番号と題名を空行で隔てる本では、目次の項目は題名の側に当たる。
番号の行は前の話の末尾に取り残される。

```
XLIX          ← ここが前の話の最後の段落になっていた

THE 'OLD BUDDHA'
```

**一語なので語数の下限では捕まらない。** 字種検査も通る。件数オラクルも通る。

### (2) 20 話の先頭に、見出しの副題や折り返しの続きが残っていた

`A STORY OF OLD JAPAN`(4018 の副題)、`HOUSE TO DEATH`(28932 の折り返し)、
`OR`(66923)。原因は、見出しの塊のうち**1 行しか飛ばしていなかった**ことである。

## 5. HC-244 — 抽出物の端は、本体とは別に検査する

`DATA-QUAL` が 2 回目(1 回目は朗読音声の README を本文として採録した件)。
共通の型は「**抽出物の端に、抽出器の想定外のものが残る/入る**」であり、
そのとき走っていた検査はすべて**テキスト全体の集計量**だった。

> 1,200 語の話に 1 語の番号が混じっても、語数も字種も件数も動かない。
> **中央は正しく、端だけが違う**という壊れ方は、集計量では見えない。

端だけを集めて出す `etl/report_edges.py` を作った。

```
709 話中、端が怪しいもの 49 件 → 直して 25 件
```

残る 25 件は一件ずつ目で通し、いずれも本文の一部であることを確かめた
(叫び声で終わる話・諺・ト書き・副題・章立ての長編)。
この件数はテストで上限として固定してある。超えたら新しい種類の混入である。

## 6. 同じ順序の誤りを、起票した直後にまた踏んだ

L4 で HC-233(上流が確定する前に重い工程を始めない)を起票した。
その直後、番号漏れを直した時点で埋め込みを始め、**そのあとに作った端の検査**が
さらに 20 話の欠陥を見つけて、本文がまた変わった。

検印(内容ハッシュ)は**入力の変化**を捕まえるが、
**「検査をこれから足す」ことは捕まえない**。
`PROC-SKIP` 3 回目として HC-233 を参照して記録した。

## 7. 訳し方について

- 段落の対応を崩さないことを最優先にした。原文が 1 段落なら訳も 1 段落
  (IN-38488-014 は 810 語がまるごと 1 段落である)
- 註の参照記号(`[7]` `[30]`)は原文の位置に残した
- `_強調_` の記法は残し、画面で斜体にする
- 韻文(ペローの教訓詩、ノルウェーの鳴き声の唱え)は散文で訳し、原文と並べて読めるようにした
- 固有名は原音に近い片仮名に寄せた(`Fionn mac Uail` → フィオン・マク・ウァル)
