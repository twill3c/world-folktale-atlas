# 古い測定の台帳(SPEC §3 G-23)

材料(コーパス・和訳・問いの集合)より古い成果物を、**理由つきで**ここに載せる。
ここに無い古さがあれば `tests/test_freshness.py` が落ちる。

**古いこと自体は禁じていない。黙って古いことを禁じている。**
測り直しには時間がかかるものがあり(NLI は CPU で数時間)、
それを理由に測定を消すのも、古い数字を新しい顔で出すのも、どちらもしたくないからである。

書き方は 1 行 1 件、`- ファイル名.json — 理由(測定時の土台)`。
`ml/freshness.py` がこの行を読む。

## いま古いもの

- `nli_eval.json` — 1,113 話(30 冊)のときの測定。全話に 21 ラベルを当てる推論が CPU で数時間かかるため、このループでは動かさなかった。判定は「不成立・画面に出さない」で、話を増やして通る種類の落ち方ではない(全ラベル付与率が 50.9% と飽和していた)。次にこの測定に触るときに測り直す

**理由の文はそのまま画面に出る。** 強調の記号(`**`)を書くと記号のまま見える。
台帳は人が読む文書であると同時に、画面の材料である。
